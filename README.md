# new_BOT

Исследовательский бот для крипто-фьючерсов Bitget: **бэктест + walk-forward проверка + монитор сигналов**.
Торговля не реализована: бот ничего не покупает и не продаёт, ключи API не нужны.

## Стратегия

Трендовая (Donchian breakout) на свечах 4H, по умолчанию BTCUSDT:

- вход в лонг: закрытие выше максимума последних 55 свечей и выше EMA 200 (шорт зеркально);
- выход: закрытие за противоположным каналом (20 свечей) или трейлинг-стоп 3×ATR;
- размер позиции: риск 1% капитала на сделку, плечо не выше 2×;
- решение принимается по закрытой свече, исполняется по открытию следующей (без заглядывания в будущее);
- учтены комиссия 0.06% и проскальзывание 0.05% на каждую сторону. **Funding не учтён.**

Трендовые стратегии обычно имеют много мелких убытков и несколько крупных прибылей, а в боковике теряют деньги.
Прибыль **не гарантирована**: прошлые результаты не предсказывают будущие.

## Как запустить

```bash
python -m unittest discover -s tests -v          # тесты
python run_backtest.py --synthetic               # офлайн-демо на случайных данных (цифры ничего не значат)
python run_backtest.py --symbol BTCUSDT --granularity 4H --days 1095
python run_backtest.py --symbol ETHUSDT --granularity 4H --days 1095
python signal_report.py                          # текущий сигнал по последним закрытым свечам
```

В GitHub Actions: **Tests** (на каждый push), **Backtest + Walk-forward** (вручную или по понедельникам),
**Signal monitor** (каждые 4 часа, только вывод в лог).

## Как читать результат

Смотрите на строку **OOS compounded return** и сравнивайте с buy&hold за тот же период. OOS (out-of-sample)
означает, что параметры подбирались на прошлом окне, а оценивались на следующем, которого бот не видел.
Результат на всём периоде с параметрами по умолчанию не является проверкой, это только ориентир.
Если OOS отрицательный или хуже buy&hold с большой просадкой, стратегию нельзя считать рабочей.

## Что дальше (по порядку)

1. Запустить бэктест на BTCUSDT и ETHUSDT и сохранить отчёты.
2. Если OOS устойчиво положительный на обоих активах, вести бумажную торговлю по сигналам минимум 2-3 месяца.
3. Только после этого рассматривать демо-исполнение на Bitget Demo с жёсткими лимитами риска.

## Известные ограничения

- `fetch_bitget` написан по публичной документации Bitget v2 и не проверялся на живом API (из среды разработки не было доступа в сеть). Если запрос вернёт ошибку, правка нужна только в `bot/data.py`.
- Внутри свечи неизвестен порядок движения цены; стоп считается сработавшим по худшему сценарию.
- Нет учёта funding, ликвидации и ограничений ликвидности.

Ключи биржи никогда не храните в коде: только в GitHub Secrets.
