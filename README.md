# new_BOT

Торговый бот для USDT-M бессрочных фьючерсов Bitget: **анализ рынка → выбор монет и стратегий → walk-forward проверка → сигналы → бумажная / демо / реальная торговля**.
Только стандартная библиотека Python 3.10+, никаких зависимостей.

> Прибыль **не гарантирована**. Прошлые результаты не предсказывают будущие. Начинайте с `--mode paper`, затем `--mode demo`, и только потом — реальные деньги в объёме, который не жалко потерять.

## Как это работает

1. **`scan_market.py`** берёт самые ликвидные USDT-M перпетуалы Bitget (по объёму за 24ч, без стейблкоинов и токенизированных акций), качает до 4 лет свечей 4H и историю funding.
2. Для каждой монеты прогоняет **все стратегии** walk-forward: параметры подбираются на 1 году, проверяются на следующих 3 месяцах, окно сдвигается. Дополнительно режим `auto` в каждом окне сам выбирает лучшую стратегию.
3. Отбирает пары монета×стратегия, которые прошли фильтры (положительный OOS, Sharpe ≥ 0.5, просадка ≤ 35%, ≥ 4 OOS-окон, ≥ 50% плюсовых окон, ≥ 10 сделок), по одной на монету и с корреляцией ≤ 0.6 между собой.
4. Делает **контрольную проверку**: тот же отбор только по данным до отсечки и проверка на последних 180 днях, которые в выбор не попадали.
5. Пишет `reports/MARKET_ANALYSIS.md` (человекочитаемый отчёт), `reports/scan.json` и `config/portfolio.json` (что торговать).
6. **`trade.py`** читает `config/portfolio.json` и после закрытия каждой свечи приводит позиции к тому, что хотят стратегии.

## Стратегии (`bot/strategies.py`)

| Имя | Тип | Логика |
|---|---|---|
| `donchian` | тренд | пробой канала N свечей по направлению EMA200, выход по каналу M, трейлинг-стоп ATR |
| `ema_trend` | тренд | быстрая/медленная EMA, вход только при ADX выше порога, трейлинг ATR |
| `supertrend` | тренд | направление Supertrend, стоп по линии Supertrend |
| `tsmom` | моментум | знак доходности за N свечей + цена выше/ниже своей средней, широкий ATR-стоп |
| `mean_reversion` | возврат к среднему | Bollinger + RSI в экстремуме при низком ADX, выход на средней или по времени |
| `auto` | мета | в каждом walk-forward окне выбирает лучшую стратегию и параметры |

Общие правила (`bot/engine.py`): решение по закрытой свече, исполнение по открытию следующей (нет заглядывания в будущее); у каждой позиции стоп, внутри свечи худший сценарий, гэп через стоп исполняется по открытию; после стопа повторный вход в ту же сторону только по новому сигналу; размер позиции = риск 1% капитала / расстояние до стопа, плечо позиции ≤ 2×; комиссия 0.06% + проскальзывание 0.05% на сторону и **реальный funding** Bitget.

## Последний анализ рынка

Полный отчёт: [`reports/MARKET_ANALYSIS.md`](reports/MARKET_ANALYSIS.md). Выбранный портфель (`config/portfolio.json`): **ENAUSDT tsmom, BTCUSDT tsmom, ETHUSDT donchian, SUIUSDT tsmom, XRPUSDT tsmom (через auto)**.
Главное, что показал анализ: на 4H лучше всего работают трендовые/моментум-стратегии (`tsmom`, `donchian`), mean reversion почти везде убыточен после издержек. Контрольная проверка на последних 180 днях дала +5.2% при просадке 19.4% против +3.7% у BTC buy&hold — это реалистичное ожидание, а не красивые +145% «портфеля целиком», в которые входит эффект подгонки отбора.

Пересчитывайте анализ раз в неделю/месяц (`scan_market.py` или workflow **Market scan**): набор монет и стратегий будет меняться.

## Запуск

```bash
python -m unittest discover -s tests -v                    # тесты

python scan_market.py                                      # анализ рынка, топ-15 ликвидных монет -> config/portfolio.json
python scan_market.py --top 30 --max-sleeves 6
python scan_market.py --symbols BTCUSDT ETHUSDT SOLUSDT

python run_backtest.py --symbol BTCUSDT                    # все стратегии на одной монете + walk-forward
python run_backtest.py --synthetic                         # офлайн-демо (цифры ничего не значат)

python trade.py --mode signal                              # что хочет каждый слот сейчас, без ордеров
python trade.py --mode paper --loop                        # бумажная торговля (state/paper_account.json)
python trade.py --mode demo --loop                         # демо-счёт Bitget
python trade.py --mode live --loop --i-understand-the-risk # реальные деньги
```

`--loop` просыпается через 30 секунд после закрытия каждой 4H свечи. Логи — `logs/`, состояние — `state/`.

### Bitget demo / live

1. В Bitget создайте API-ключ (для demo — в режиме Demo Trading) с правами на фьючерсы, **без права вывода**, желательно с привязкой к IP.
2. Счёт USDT-M: режим позиций **one-way**, маржа **cross**.
3. Ключи только через переменные окружения (никогда не в код и не в git):
   ```bash
   export BITGET_API_KEY=...  BITGET_API_SECRET=...  BITGET_API_PASSPHRASE=...
   export TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=...   # необязательно: уведомления о сделках
   ```
4. Demo-режим отправляет заголовок `paptrading: 1`. Live требует явного флага `--i-understand-the-risk`.

Стоп-лосс каждой позиции стоит **на бирже** (`presetStopLossPrice` при входе, затем `pos_loss` для трейлинга), поэтому если бот упал, позиции не остаются без защиты.

### Лимиты риска в `trade.py`

- риск на сделку и плечо слота — из `config/portfolio.json` (1%, 2×);
- `--max-total-leverage 3` — суммарный номинал всех позиций ≤ 3× капитала;
- `--max-daily-loss 0.05` — при просадке 5% за UTC-день всё закрывается и торговля встаёт до следующего дня.

## GitHub Actions

- **Tests** — на каждый push / PR.
- **Market scan** — по понедельникам или вручную; отчёт и `portfolio.json` в артефактах.
- **Backtest + Walk-forward** — вручную для одной монеты.
- **Signal monitor** — каждые 4 часа печатает сигналы портфеля (без ордеров).

## Известные ограничения

- Отбор лучших пар из многих вариантов завышает OOS-цифры (multiple testing). Ориентируйтесь на контрольную проверку и бумажную торговлю.
- Внутри свечи порядок движения цены неизвестен — стоп считается по худшему сценарию; ликвидация и глубина стакана не моделируются (при плече ≤ 2× и стопе ликвидация маловероятна).
- В бэктесте «портфеля целиком» каждый слот может держать до 2× плеча; в `trade.py` дополнительно действует общий лимит 3×.
- `BitgetBroker` проверен на подписи и формате запросов (моки), но реальные ордера из среды разработки не отправлялись: сначала прогоните `--mode demo`.
